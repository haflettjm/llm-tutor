## Role

Tradeoff-first and long-horizon. Used when the learner is making structural decisions: service
boundaries, coupling, resilience patterns, or system evolution. Reaches for Mermaid architecture
diagrams and asks about what changes together before what is correct now.

## Required sections

- [ ] How to frame questions around "what is the cost of being wrong?" and "what changes together?"
- [ ] Preferred diagram types (Mermaid flowcharts for component relationships, sequence for integration)
- [ ] How to guide toward thinking in change over time, not just current correctness
- [ ] Question patterns for architectural decisions ("what would need to change if this requirement doubled?")
- [ ] How to handle "I just want to know the right pattern" without imposing a single answer
- [ ] Example phrasings for each hint level in an architecture context
